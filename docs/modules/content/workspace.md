# 附件工作区与冲突处理

每个档案有独立附件 scope 和根目录。文件与文件夹都拥有稳定 ID、父节点、名称和节点版本；空目录也是显式节点。文件列表、冲突摘要和卡片尽量使用同一套路径与展示规则，不能分别推断文件身份。

## 名称与目录

名称比较使用 NFC 规范化后转小写的 `name_key`，数据库同父目录唯一键、服务端预检和前端规划遵守同一规则。完整路径有 UTF-8 字节预算，文件夹改名时也校验全部后代的新路径。

上传／替换统一小写真实扩展名。重命名只编辑文件名主体，扩展名和文件自身的 `.good` 尾缀保持锁定；机密状态通过专门操作改变。输入框复用 `MyFileNameInput`，自动清洗规则与服务端名称校验共同约束，前端清洗不取代服务端校验。

文件夹和文件可以使用同一 `set_private` 通道改变机密声明。机密目录的后代继承访问属性；继承状态不能在子文件上单独取消。移出机密目录会重新按目标路径计算继承，不凭旧 `is_private` 为子文件永久追加标记。详细示例见[访问控制](access.md)。

## 并发与预约

普通改名、移动、删除等操作走短事务，附带 `request_id`、目标 ID 与版本。当前仓库实现会锁定对应档案行以串行提交 scope 内的工作区变化；不能将其描述成数据库已经具备完全独立的任意路径并行锁。

长时间上传不持有数据库事务锁。上传会话持久预约目标父目录／名称以及替换源；唯一约束阻止冲突预约，后续分片、发布和取消根据会话事实处理。

前端按操作涉及的节点、路径和子树，以及服务端预约信息计算可执行性。一个文件上传时，无关文件仍可操作。目录删除、改变继承权限等涉及整棵子树的动作，还要检查内部预约和替换源。

同一 `request_id` 的成功或明确整批拒绝会留下回执。网络错误造成结果未知时，重试原请求以对账；只有用户修改了明确冲突的处理策略，才创建新请求。重复请求的权限仍会重新检查。

命令接口在事务提交后返回当前访问者可见的最新工作区，前端先合入共享列表再结束转圈，不等待 outbox／MQTT 通知。通知仍负责其他页面和客户端的同步；较旧的同身份快照不能覆盖较新的命名空间版本。若提交成功但读取快照失败，仍以原 `request_id` 重试取回当前状态，避免重复执行；快照不存入命令回执。

## 批量与 resolve

批次先完整规划，存在未处理冲突时整批不执行。服务端返回冲突类别、目标及该类别允许的策略，前端不能自行跳过未知错误。

| 类别 | 可选处理 |
| --- | --- |
| 名称冲突／上传预约 | 报错、跳过、自动后缀 |
| 源目标忙碌 | 报错、跳过 |
| 非法名称 | 报错、跳过、清洗 |
| 已有删减版 | 报错、跳过此次覆盖、保留、删除 |
| 其他 | 报错、跳过 |

resolve 对话框按理由分组，标题行可展开／折叠，默认折叠；『其余 N 项无错误』采用同样结构。确认按钮固定为『重试』。每个文件无需重复组标题已经表达的理由；路径摘要补齐祖先目录，只有真正冲突节点显示错误色。

选定策略后会重新验证整批当前状态，原来无错误的项也参加重试。『保留旧删减版』是明确选择，并不表示新图片已经重新审核了旧删减内容。

## 列表交互

- 支持单选、范围／多选与右键菜单，包括普通、失败和进行中的上传任务。
- 正式文件选择与上传任务选择互斥；选择目录时剔除重复的后代选项。
- 批量动作根据适用项筛选选择；不把已被自动排除的项目继续算入禁用理由。
- 替换进行时，用上传任务行占据旧文件的位置，并采用任务菜单；取消后恢复旧文件行。发布时同步接受新工作区，避免任务和文件同时出现或暂时都不出现。
- 机密文件显示锁与颜色；机密目录只变色。有删减版的机密文件显示蓝色，未有删减版时使用机密色；错误、活动任务等状态有自己的优先级。
- 删除检查已保存引用和当前草稿引用；删除目录还检查其后代。删除删减版有单独确认，保留原附件行。
