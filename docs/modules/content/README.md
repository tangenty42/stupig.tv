# Content：档案与附件

Content 管理『蠢猪档案』：以 Markdown 保存档案正文和元数据，以附件工作区组织文件，通过角色权限提供公开与机密视图。当前运行时要求 Content 数据已迁入新工作区与阿里云 OSS；仍带旧加密材料或旧存储身份的数据会拒绝进入正常读取／编辑流程。已有生产数据的切换见[迁移手册](../../operations/content-cutover.md)。

## 业务入口

| 页面／入口 | 用途 |
| --- | --- |
| `/content` | 档案列表，使用标题、标签、时间、评分与封面等摘要 |
| `/content/:id` | 当前访问者有权看到的正文与附件 |
| `/content/:id/edit` | 正文编辑、草稿、附件工作区、图片编辑和预览 |
| `content` tRPC router | 档案、工作区、上传会话、引用重放及下载签发 |
| `/api/content/attachments/:id` | 绑定附件身份和版本的读取入口 |
| `/api/content/authorize` | ESA 的在线授权回调；不传输附件字节 |

档案元数据位于正文开头的 front matter：标题、标签、事件日期、说明和封面。事件日期支持日／月精度。评分和置顶通过共享规则解释，普通标签与内部标记在展示时分别处理。准确语法和校验见 [Markdown 与引用](markdown.md)。

## 数据与身份

| 对象 | 当前事实及用途 |
| --- | --- |
| 档案 | `content_stories` 中的正文、摘要和正文 revision |
| 工作区 | 每个档案的 scope、根目录、显式父子关系、稳定节点 ID |
| 附件 | 逻辑名称、路径、节点版本、当前对象及授权属性 |
| 图片表示 | 同一附件行中的原图、AVIF、JPEG 与可选删减版 |
| 上传会话 | 上传意图、目标预约、尝试、分片与最终发布回执 |
| 引用历史 | 路径命名空间、档案标题的变化及草稿可用基线 |
| 后台账本 | 图片、对象退役、预热、通知等领域事实 |

名称和对象 key 是两种身份。改名／移动改变逻辑路径和引用，不复制 OSS 字节；替换保留附件 ID，发布新的不可变对象和版本。正文只保存 `att://`／`content://` 引用，不存对象 key 或短期签名地址。

前端分别维护正文、附件工作区、本人上传会话和 scope 预约。`viewer_key` 区分身份相关投影；正文 revision、命名空间 revision、标题 revision 和附件版本分别守住各自的并发边界。

## 主要流程

1. **正文编辑**：载入当前权限投影及引用基线，恢复本地草稿；保存时校验正文与引用历史，遇到并发变化要求处理。
2. **上传／替换**：整批预检并预约目标，浏览器直传分片；服务端核验对象，图片完成处理后以事务发布附件、引用变化和通知。
3. **目录操作**：短事务处理改名、移动、删除和机密标记，复核版本、预约、引用和权限，并记录幂等回执。
4. **读取**：服务端生成当前允许的附件投影，ESA 在每次请求交付前回调应用复核授权，随后由原生缓存／OSS 交付字节。
5. **物理维护**：后台异步预热已发布表示、回收取消尝试、退役旧对象并刷新缓存；它们不替代数据库的发布与撤权。
