# 上传、替换与恢复

普通上传、替换、图片编辑输出和删减版输出共享上传会话入口。浏览器负责文件字节与传输，服务端负责目标预约、授权、完整性和正式发布。HTTP 上传完成不等于附件已经发布。

## 接入与文件类型

支持多文件选择、文件夹选择、拖放与粘贴。文件夹上传保留相对目录层级，并通过 `selection_root` 表达选中的根；`.good` 文件和 `.good` 目录按路径继承机密属性，字节仍保持原文件格式。

客户端读取文件大小和选择元数据，批次携带目标、操作意图及可选源附件版本，不预先扫描文件或提交整文件 SHA-256。服务端按统一规则校验名称、权限、占用、文件大小和操作一致性，整批无未解决冲突后建立会话。

选择完成即显示文件行及受理状态，不额外显示批次状态栏。加号保持添加图标，受理未结束时暂停重复选择；本地预检失败可通过右键菜单『取消准备』清理。受理请求已经发出后先确认其幂等结果，再通过真实上传会话取消，不把本地清空当作服务端取消。身份切换拒绝迟到结果；文件大小和批次数量在读取字节前按客户端现有上限预检。

首次上传直接读取待传分片，浏览器计算该片 MD5，服务端先固定分片编号、长度与 MD5，再签发上传授权，OSS 校验收到的分片。准备行按真实会话 ID 衔接上传行；新目录尚未进入独立工作区快照时，上传任务先以完整路径显示在根层。

继续上传时，服务端从 OSS 查询并核对已经上传的分片与已签发承诺。浏览器校验所选文件总大小，并仅读取这些已上传分片对应的范围，与各片 MD5 比较，通过后才继续发送缺失分片。校验可暂停；选错文件后清理该字节源及其持久化句柄，允许重新选择。它保证已上传部分与当前选择一致，不证明尚未上传的部分与最初选择相同，也不把文件名和大小当作内容一致证明。

完成时，服务端检查分片连续、数量与长度完整，按已确认 ETag 清单请求 OSS 合并，并核对合并回执、对象大小、private ACL、ETag 与 version ID；事务中的权限、执行权和发布版本检查照常执行。ETag 用于身份核对，不当作整文件 MD5。普通上传不从 OSS 全量读回计算 SHA，完成回执中的 `sha256` 为 `null`，也不会伪造摘要或自动增加后台摘要任务。现存受理意图中的 SHA 字段仅供持久化记录解析，不再作为上传前置条件；新增受理不携带它。

### 统一对象校验与摘要存储

普通附件封存、云端图片来源／产物和原图归档共用 [OSS 对象身份校验](../../../server/lib/oss-object-identity.ts)：并行读取 HEAD 与对象 ACL，要求有效 ETag、version ID、非负整数大小和显式 private；已有预期身份时逐项匹配。封存最终检查再次核对 ACL，发现对象身份或权限变化时不写成功回执。这只验证存储身份和操作结果，不是服务器独立重算完整内容摘要。

`content_transfer_attempts.sha256` 是既有可空列；会话 `result` 及图片 `image_metadata`／`redacted_metadata` 的各对象角色也可在 JSON 中记录 `sha256`。`null` 表示没有计算或取得可信整文件 SHA-256，不表示空文件或上传失败；已有真实摘要保留。没有新增列，也不以分片 MD5、ETag 或 CRC64 代替 SHA-256。

图片编辑输出与删减版格式检查仍通过精确 Range 读取最多 12 字节检查文件头；OSS 忽略范围或返回不符时失败。云端图片另读有界 `image/info` 核对实际格式、帧数、尺寸与方向，仅读取 24px LQIP，不回读整图或重新计算整图 SHA。原图归档核对条件复制的来源版本与目标回执。运行时本地编码已退役，完整字节摘要校验仅保留给冻结迁移及离线诊断，具体见[图片与删减版](images.md#运行时本地处理退役)。

| 文件类型 | 上传后处理 |
| --- | --- |
| 静态 JPEG、PNG、WebP、AVIF | 进入受预算限制的图片处理管线，生成正式图片模型 |
| GIF、SVG 等其他图片 | 按原始字节上传，不转换、不提供图片编辑 |
| 非图片文件 | 按原始字节上传 |

浏览器声明的 MIME 和文件名是输入线索，图片处理阶段还会验证实际内容、帧数、尺寸和格式。格式损坏或超预算不会作为就绪图片发布。具体图片合同见[图片与删减版](images.md)。

## 会话流程

```text
预检与预约 → 初始化尝试／multipart → 分片直传 → seal 与完整性核验
                                                   ↓
                       普通对象 ready ／ 图片处理并验证 ready
                                                   ↓
                           adopt 事务 → 正式附件 + 工作区 + 通知回执
```

分片授权绑定会话、分片号及 MD5，浏览器直接 PUT 到 OSS；应用不转发完整文件字节。服务端持有 upload ID 和已确认分片事实。恢复时重新查询并核对远端状态，不能仅相信浏览器进度条。

会话 API 会把具备核验结果的内部 `verifying` 状态投影成 `ready`。图片还有自己的处理状态，两者不能合并成一个任意比例进度。正式发布事务同时处理节点、对象采用、引用历史和 outbox；采用对象前检查退役墓碑，避免清理与发布竞态。

对象提交响应丢失时，通过已记录的尝试和对象身份对账。取消、过期或旧代次不能靠迟到响应重新发布。

## 暂停、继续与重新选文件

暂停是浏览器停止当前传输 driver，已有服务端会话和预约继续存在，仍受有效期限制。取消会请求服务端撤销会话；如果此前已正式完成，客户端先读取回执，不把已发布文件误判为未完成任务删除。

支持的浏览器可以把真实文件句柄保存在 IndexedDB，供刷新后恢复。权限变化时先检查权限，不在用户已撤权后自动读取旧句柄；需要重选时从原会话选择文件，并复核总大小和已上传分片 MD5 后继续。没有可恢复句柄的浏览器需要用户重新选择文件；内存中的 `File` 不属于正文草稿的持久化内容。

本人会话可以携带继续传输所需的信息；其他操作者只看到 scope 占用投影。身份切换会重置客户端上传状态并拒绝迟到的旧身份快照。

## 替换与发布衔接

替换保留附件稳定 ID。『保留原名称』保留原主体名称，真实扩展名和 MIME 随新文件更新；不会把 GIF 字节伪装成原来的 PNG。新对象发布前原附件仍可读取。

已有删减版时，普通覆盖／替换需要 resolve 明确选择保留、删除或取消此次覆盖。文件名、权限、源版本或预约发生变化时重新校验；不能因为最初选过文件就绕过当前状态。

客户端维护 finalizing 状态，从 seal／处理／adopt 直到接受工作区及正文引用同步的衔接保持保护，避免慢网速时『文件已上传、正文仍在替换』期间覆盖用户新输入。正文编辑器的只读策略见[草稿与引用同步](drafts.md)。

任务行直到结果对账完成才交接给正式文件行。会话列表暂时缺失某条记录不会直接抹去本地任务，会按 ID 查询确认。

## 清理与验证

### 上传耗时与资源观测

服务端使用现有 JSON 行日志输出 `msg: upload_stage`，以 `session_id`、`job_id`、`execution_epoch` 关联上传和图片尝试。字段只含固定阶段、耗时、返回／拒绝结果和累计数据库连接获取耗时；不记录文件名、正文、对象 key、SQL、签名 URL 或异常原文。观察入口见 [`upload-observation.ts`](../../../server/lib/upload-observation.ts)。

| 阶段 | 测量范围 |
| --- | --- |
| `upload_seal` / `multipart_complete` | 封口 API 全程／实际 OSS 合并请求；已完成对象重读不会伪造一次合并 |
| `image_claim` / `image_queue` | 认领事务／认领 SELECT 开始时的数据库时间减最后 queued 时间；队列值在成功认领后记录，不含该语句自身的锁等待，重领 processing 不冒充新入队 |
| `image_job` | 认领后的处理、归档、ready 提交和在途分支排空 |
| `image_ready_commit` | 处理完成后的租约复核、ready 结果及其 outbox 事务提交 |
| `image_source_guard` / `image_final_guard` | 管线首尾已有的对象身份／ACL 与租约检查，不新增请求 |
| `image_source_info` / `image_display` / `image_fallback` / `image_lqip` / `image_archive` | 源信息、WebP、JPEG、LQIP 读取／小图头验证及原图归档；派生阶段包含自身已有的身份检查和检查点 |
| `upload_adopt_commit` / `upload_adopt` | 采用事务（含幂等重放）／前台采用 API 及提交后的工作区读取；后台采用也记录前者 |
| `sync_queue` / `sync_publish_ack` | 上传会话通知的建账到认领时间（含重试等待）／MQTT 发布确认；不表示浏览器已收到或渲染 |

每个阶段的 `returned` 只表示该调用正常返回，`failed` 包括取消和被拒绝的尝试；不能单凭一行记录推断最终发布成功。父子阶段与并行归档存在重叠，不能直接相加。队列使用数据库语句开始时的时钟，其余耗时使用本机单调时钟；不跨主机相减。后台扫描和每条上传任务建立独立观测上下文，不继承唤醒它的前台请求身份或连接等待计数。

管理员现有 `admin.getBackgroundStatus` 返回 `observations` 与 `resources`：固定阶段的进程累计次数、拒绝次数、当前／峰值在途数、总耗时、最大值，以及每阶段最近最多 128 次的 P50／P95 和实际样本数。样本少时不是生产容量承诺；重启会清零，不是持久化账本或集群指标。`resources` 为当前 Node 进程的 RSS／heap／external 字节、运行秒数及累计 CPU user/system 毫秒，不是单张图片 CPU 或峰值内存。

`db_acquire` 在 mysql2 的公开 callback pool 获取连接入口测量，因此覆盖 `execute`、`query` 和显式事务。它的在途数表示尚未得到连接的请求；耗时包含排队及新建连接，不是 SQL 执行或锁等待。阶段日志的 `db_acquire_ms` 是该阶段所有连接获取的累计值，嵌套／并行请求可能使它超过墙钟耗时。逐条 SQL 不增加日志。

浏览器在原生 Performance 时间线保留最近最多 128 个 `content.upload.<session_id>.*` measure，可在本次上传所在的编辑页控制台读取：

```js
console.table(performance.getEntriesByType('measure')
  .filter(item => item.name.startsWith('content.upload.'))
  .map(item => ({ name: item.name, duration_ms: item.duration })))
```

阶段包括句柄回读 `source`、`resume`、`initialize`、续传 `checking`、`bytes`、`seal`、`await_completion`、`adopt`、`dom_update` 和 `total`，末尾带 returned／failed／stopped。`bytes` 包含 SDK 分片准备、MD5、签名及传输；`await_completion` 是客户端收到封口结果后等待状态回传的时间，不能当纯编码时长。`total` 从当前页面本次执行开始，到接收采用结果、工作区与落地回调交接并完成 Vue `nextTick`；不包含此前的文件选择／受理，不保证图片已解码或绘制。刷新恢复可能只有后半段，暂停／失败分别结束本次观测，不把恢复前的时间补成假数据。通知早于 HTTP 响应时，各调用仍独立等自己的响应再结束计时；DOM 观测不延长 finalizing 围栏。

浏览器数据留在当前页面，不上报新接口；Performance 不可用或日志失败不改变业务结果。当前生产应用进程的观测应从管理员 API 读取；源码 `background:status` CLI 是另一个进程，只能看到自身观测，不能代替应用进程指标。部署后用代表性小图、照片和编辑输出重测整条链路；离线 fixture 的延迟不代表生产 OSS。

2026-11-02 的[脱敏验证](../../reviews/upload-observability-2026-11-02.json)包括开发桶真实调用、隔离数据库混合负载／连接池占满及浏览器 Performance 断言。开发桶各一次：460 字节 JPEG 约 2.03s，2,621,740 字节 PNG 约 1.78s；前者 JPEG 与尾部检查阶段约 0.90／0.50s，后者 WebP 阶段约 1.32s。阶段包含关联请求／校验，不是云端纯编码 CPU 时间，也不是生产 P95。两轮共 16 个专用对象均已软删除并确认当前缺失，历史版本保留；隔离数据库与浏览器测试实例已清理。

会话过期、取消、被替代的尝试由上传生命周期扫描处理，包括普通文件和图片输入。暂存 key 可能已被正式普通附件采用，不能按 `staging/` 前缀直接删除；见[对象生命周期](object-lifecycle.md)。
