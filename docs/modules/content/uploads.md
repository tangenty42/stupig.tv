# 上传、替换与恢复

普通上传、替换、图片编辑输出和删减版输出共享上传会话入口。浏览器负责文件字节与传输，服务端负责目标预约、授权、完整性和正式发布。HTTP 上传完成不等于附件已经发布。

## 接入与文件类型

支持多文件选择、文件夹选择、拖放与粘贴。文件夹上传保留相对目录层级，并通过 `selection_root` 表达选中的根；`.good` 文件和 `.good` 目录按路径继承机密属性，字节仍保持原文件格式。

客户端读取文件大小和选择元数据，批次携带目标、操作意图及可选源附件版本，不预先扫描文件或提交整文件 SHA-256。服务端按统一规则校验名称、权限、占用、文件大小和操作一致性，整批无未解决冲突后建立会话。

选择完成即显示文件行及受理状态，不额外显示批次状态栏。加号保持添加图标，受理未结束时暂停重复选择；本地预检失败可通过右键菜单『取消准备』清理。受理请求已经发出后先确认其幂等结果，再通过真实上传会话取消，不把本地清空当作服务端取消。身份切换拒绝迟到结果；文件大小和批次数量在读取字节前按客户端现有上限预检。

首次上传直接读取待传分片，浏览器计算该片 MD5，服务端先固定分片编号、长度与 MD5，再签发上传授权，OSS 校验收到的分片。准备行按真实会话 ID 衔接上传行；新目录尚未进入独立工作区快照时，上传任务先以完整路径显示在根层。

继续上传时，服务端从 OSS 查询并核对已经上传的分片与已签发承诺。浏览器校验所选文件总大小，并仅读取这些已上传分片对应的范围，与各片 MD5 比较，通过后才继续发送缺失分片。校验可暂停；选错文件后清理该字节源及其持久化句柄，允许重新选择。它保证已上传部分与当前选择一致，不证明尚未上传的部分与最初选择相同，也不把文件名和大小当作内容一致证明。

完成时，服务端检查分片连续、数量与长度完整，按已确认 ETag 清单请求 OSS 合并，并核对合并回执、对象大小、private ACL、ETag 与 version ID；事务中的权限、执行权和发布版本检查照常执行。ETag 用于身份核对，不当作整文件 MD5。普通上传不从 OSS 全量读回计算 SHA，完成回执中的 `sha256` 为 `null`，也不会伪造摘要或自动增加后台摘要任务。现存受理意图中的 SHA 字段仅供持久化记录解析，不再作为上传前置条件；新增受理不携带它。

图片编辑输出与删减版格式检查仍通过精确 Range 读取最多 12 字节检查文件头；OSS 忽略范围或返回不符时失败。图片处理需要解码字节，会在这次已有读取中计算输入 SHA，继续保留图片产物与原图归档验证，具体见[图片与删减版](images.md)。这些验证不属于普通附件上传后的整文件复读。

| 文件类型 | 上传后处理 |
| --- | --- |
| 静态 JPEG、PNG、WebP、AVIF | 进入受预算限制的图片处理管线，生成正式图片模型 |
| GIF、SVG 等其他图片 | 按原始字节上传，不转换、不提供图片编辑 |
| 非图片文件 | 按原始字节上传 |

浏览器声明的 MIME 和文件名是输入线索，图片处理阶段还会验证实际内容、帧数、尺寸和格式。格式损坏或超预算不会作为就绪图片发布。具体图片合同见[图片与删减版](images.md)。

## 会话流程

```text
预检与预约 → 初始化尝试／multipart → 分片直传 → seal 与完整性核验
                                                   ↓
                       普通对象 ready ／ 图片处理并验证 ready
                                                   ↓
                           adopt 事务 → 正式附件 + 工作区 + 通知回执
```

分片授权绑定会话、分片号及 MD5，浏览器直接 PUT 到 OSS；应用不转发完整文件字节。服务端持有 upload ID 和已确认分片事实。恢复时重新查询并核对远端状态，不能仅相信浏览器进度条。

会话 API 会把具备核验结果的内部 `verifying` 状态投影成 `ready`。图片还有自己的处理状态，两者不能合并成一个任意比例进度。正式发布事务同时处理节点、对象采用、引用历史和 outbox；采用对象前检查退役墓碑，避免清理与发布竞态。

对象提交响应丢失时，通过已记录的尝试和对象身份对账。取消、过期或旧代次不能靠迟到响应重新发布。

## 暂停、继续与重新选文件

暂停是浏览器停止当前传输 driver，已有服务端会话和预约继续存在，仍受有效期限制。取消会请求服务端撤销会话；如果此前已正式完成，客户端先读取回执，不把已发布文件误判为未完成任务删除。

支持的浏览器可以把真实文件句柄保存在 IndexedDB，供刷新后恢复。权限变化时先检查权限，不在用户已撤权后自动读取旧句柄；需要重选时从原会话选择文件，并复核总大小和已上传分片 MD5 后继续。没有可恢复句柄的浏览器需要用户重新选择文件；内存中的 `File` 不属于正文草稿的持久化内容。

本人会话可以携带继续传输所需的信息；其他操作者只看到 scope 占用投影。身份切换会重置客户端上传状态并拒绝迟到的旧身份快照。

## 替换与发布衔接

替换保留附件稳定 ID。『保留原名称』保留原主体名称，真实扩展名和 MIME 随新文件更新；不会把 GIF 字节伪装成原来的 PNG。新对象发布前原附件仍可读取。

已有删减版时，普通覆盖／替换需要 resolve 明确选择保留、删除或取消此次覆盖。文件名、权限、源版本或预约发生变化时重新校验；不能因为最初选过文件就绕过当前状态。

客户端维护 finalizing 状态，从 seal／处理／adopt 直到接受工作区及正文引用同步的衔接保持保护，避免慢网速时『文件已上传、正文仍在替换』期间覆盖用户新输入。正文编辑器的只读策略见[草稿与引用同步](drafts.md)。

任务行直到结果对账完成才交接给正式文件行。会话列表暂时缺失某条记录不会直接抹去本地任务，会按 ID 查询确认。

## 清理与验证

会话过期、取消、被替代的尝试由上传生命周期扫描处理，包括普通文件和图片输入。暂存 key 可能已被正式普通附件采用，不能按 `staging/` 前缀直接删除；见[对象生命周期](object-lifecycle.md)。

自动测试覆盖分片、完整性、权限、未知结果、取消与发布竞态、finalizing 交接。浏览器验收应分别进行多文件和文件夹上传、`.good` 继承、慢网速替换、暂停刷新、原生句柄撤权重选、失败任务多选和取消后恢复。
