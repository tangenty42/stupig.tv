# 备份、恢复与回滚

仓库提供迁移回执、对象生命周期控制和部署失败恢复，但没有完整的自动备份调度、业务回收站或通用数据 down。生产备份位置、保留周期和恢复目标需要由运维明确配置并演练，不能根据 OSS 开启版本控制就判定已具备完整恢复能力。

## 需要共同保留的材料

| 材料 | 内容与用途 |
| --- | --- |
| 数据库一致性备份 | 业务表、会话／权限、迁移账本、对象生命周期与通知账本 |
| 对象清单及版本 | 提供方、桶、精确 key、version ID、大小和摘要；区分普通、原图、派生图、删减版 |
| 环境与发布身份 | 源码 commit、镜像 ID、对应 Compose、配置层和受控保存的密钥版本 |
| ESA 配置 | 函数发布版本、环境变量快照、路由／缓存／响应头／回源规则 |
| 历史迁移材料 | 源快照、旧 AES 材料、对象回执和 pin；适用旧 Content 切换 |
| 其他服务配置 | 数据库／Redis 持久化策略、EMQX 认证与 ACL、反代／TLS、RAM 策略 |

数据库快照中的旧 AES key、会话和业务正文按敏感数据保护。配置加密文件与解密口令不要保存在同一个公开位置；恢复步骤需要验证密钥仍可用，但不输出内容。

## 当前工具能做什么

- `.env.prod.gpg` 是生产环境文件的加密交付物，`pnpm env:check` 用于核对交付一致性；它不备份数据库和云端控制台设置。
- 部署脚本切换前备份 `.env.prod`、Compose 和旧 image ID。配置校验、拉取或健康门失败时尝试恢复它们；已提交的数据库迁移不会回滚。
- `pnpm db:dump:dev` 修改手机号、bcrypt 哈希和 IPv4，用于开发样本导出。它改变了身份数据，**不能作为生产恢复备份**，也不能保证所有隐私字段已脱敏。
- OSS 当前版本删除、历史版本生命周期及永久删除是不同操作，实际保留能力需核对[桶配置](../deployment/oss.md)。旧版本还在不代表应用中存在可点选的恢复入口。

## 维护前备份流程

1. 确认目标环境、数据库、对象桶、应用版本和相关服务。
2. 对跨数据库／对象变更安排写入冻结，停止应用、独立 worker 和旧清理 cron；记录仍在云端执行的任务。
3. 通过现有受控 MySQL 备份方案导出一致性快照，连同必要的日志和时间点信息保存。备份工具、加密、保留与异地策略由服务器部署决定，仓库未替这些方案做自动配置。
4. 保存对象版本清单及恢复所需的配置、账本和凭据版本。禁止在日志中展开密钥。
5. 在隔离环境恢复并核对业务数据、授权及文件摘要；确认可以恢复后再开始维护写入。

不要把新备份覆盖到唯一旧备份上。备份验收应记录实际恢复结果，单纯文件存在或导出命令退出成功不足以证明可恢复。

## 部署失败

先阅读 CI/SSH 输出，确认失败发生在配置切换、镜像拉取、启动迁移还是健康检查。保留 `.env.prod.bak`、`docker-compose.yml.bak`、旧 image ID 和容器日志，核对自动恢复是否完成。

在部署目录可先执行只读诊断：

```sh
docker compose --env-file .env.prod ps
docker compose --env-file .env.prod logs --tail 100 app
docker compose --env-file .env.prod exec app node .output/server/maintenance/migrate.mjs --status
```

若容器尚未运行，最后一条不能执行；改用已确认版本的一次性维护容器，见[迁移手册](./migrations.md#生产产物与维护容器)。不要因旧镜像健康就认为新迁移已撤销。新旧应用数据库合同不兼容时，先维持维护状态并选择兼容的恢复方案。

首次部署没有旧镜像可恢复；自动恢复失败时也需要人工处理。现行 ACR 流程主要发布 `latest`，因此长期回退不能依赖某个 SHA tag 必然存在；应保存明确 image ID／构建身份，按[GitHub 与 ACR](../deployment/github-acr.md)说明重建匹配版本。

## 数据或对象误操作

1. 停止继续写入和相关退役扫描，保留当前账本与对象状态；暂停扫描不等于已发送的云端请求全部停止。
2. 明确目标时间点、受影响 scope／附件 ID、key 和 version ID。
3. 在隔离环境还原数据库及对象，验证文件内容、引用、权限和应用版本兼容性。
4. 制定受控恢复：数据库指针、对象可用性与读取 revision 必须协调；不能只恢复一个 key 就重新开放读取。
5. 验证 ESA 授权、缓存与后台生命周期后恢复服务，处理恢复点之后的合法增量。

项目当前没有一条可安全覆盖所有误删除场景的恢复命令。需要具体恢复迁移时，应按现状设计、预演并验证；不直接改 completed 回执，不删除 migration pin 来绕过校验。

## 仍需部署时明确的项目

- 数据库备份频率、保留期、加密与恢复时间／数据丢失目标。
- OSS 历史版本保留及生命周期实际生效范围。
- 备份和云端控制台规则的独立保存位置及访问权限。
- 恢复演练周期，以及谁有权限执行停机、回滚和永久删除。

这些属于部署责任，不能把未配置的策略写成当前已具备的能力。
