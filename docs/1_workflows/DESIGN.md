# DESIGN：工作流程总览

- 本文档状态：DONE
- 覆盖范围：初次配置、开发、测试、构建、部署、维护

## 阶段

| 阶段 | 覆盖范围 | 文档 |
| --- | --- | --- |
| 初次配置 | 本机工具、阿里云资源、服务器、GitHub 与 ACR 的初次配置 | `SID#1.0` |
| 开发 | 环境搭建、日常启动、配置准备、数据库结构变更、代码提交 | `SID#1.1` |
| 测试 | 改了什么之后要跑什么测试、CI 查什么 | `SID#1.2` |
| 构建与部署 | 合并上线流程、停机措施、失败回退机制 | `SID#1.3` |
| 维护 | 迁移、备份恢复、后台任务、排障 | `SID#1.4` |

## 环境

| | 开发（dev） | 生产（prod） |
| --- | --- | --- |
| 应用 | 本机启动 Nuxt 开发服务 | 服务器 Docker 容器运行构建产物 |
| EMQX | 本机 Docker（`docker-compose.dev.yml`） | 随应用由生产 Compose 部署 |
| MySQL、Redis | 本机 Docker（`docker-compose.dev.yml`） | 服务器环境独立维护 |
| 环境变量 | `.env.dev`，不入库 | `.env.prod`，加密为 `.env.prod.gpg` 入库 |
| 上线方式 | — | 推送到 `main` 且 Check 通过后，由 Deploy 自动部署；只改文档的推送不触发；含维护迁移的版本须手动确认 Maintenance Deploy |

`:dev` / `:prod` 后缀用于区分目标环境。执行会连接生产设施的命令前，务必确认执行目标、操作模式。

架构与配置的组织方式详见 `SID#0.1.DESIGN`。
