### 2026-11-20 视图切换不再闪动

闪动不是地址参数引起的重挂载（Nuxt 默认页面 key 不含 query），实测用 MutationObserver 与逐帧采样确认：切换到任一顶层 await 首次取数的视图时，页面级 Suspense 回退把整个 main 清空；切到不同步取数的视图时，列表自己渲染骨架行，内容区缩到一行再逐帧展开。

修法：两个视图（`MyAdminRunView`、`MyContentStoryDraftList`）都在顶层 await 其 `ready`，页面用 `<Suspense suspensible>` 包住切换的组件根（[admin/index.vue](../../../app/pages/admin/index.vue)、[content/index.vue](../../../app/pages/content/index.vue)）。切换时旧视图留在屏幕上，新视图拿到首份数据后一次换上；超 150ms 未就绪整块淡到 60% 并标 `aria-busy`。切换按钮立刻反映选择，一级标题、轮询周期、档案数量和事件日历跟随 `@resolve` 时实际显示的视图。蠢猪档案的已发布列表抽成 [PublishedList.vue](../../../app/components/MyContent/Story/PublishedList.vue)，筛选和排序状态留在页面，来回切换不丢。

水合是这次的坑：`server: false` 的查询在 SSR 不取数，若水合期间被顶层 await 阻塞，客户端会先拿到真实数据再比对 SSR 骨架，报 hydration mismatch。所以两个视图都在 `useNuxtApp().isHydrating` 时跳过 await——水合按 SSR 骨架完成后由浏览器自行取数，与改动前一致。约定写进了 [SID#0.1.AGENT-DESIGN](../../../docs/0_overall/1_architecture/AGENT-DESIGN.md#前端组件与样式)。

验证：改动文件的 ESLint、`pnpm typecheck`、`pnpm test:component`（pages、MyAdmin、MyContent/Story 共 29 项）通过；`pnpm test:e2e tests/e2e/admin-views.spec.ts tests/e2e/content-draft-cards.spec.ts tests/e2e/content-draft-discard.spec.ts tests/e2e/content-cloud-draft.spec.ts` 在隔离库与临时 MQTT 上 5 条用例通过。临时诊断 spec（逐帧采样 + MutationObserver）确认：两个页面双向切换全程无空白帧，旧视图保持到切换完成；诊断文件已删除。

### 2026-11-20 卡片色边、明细重设计与一次排查

同日人类再调版式：『TODO』卡片去掉浮在左缘的竖标，改为左边框加粗到 3px 并按类别着色；『查看明细』在明细已展开时也立即重读当前页（`StorageFindings` 暴露 `refresh`）；明细区顶部一行与刷新按钮改为顶对齐；仪表盘卡标题图标配色块间距加大。

『后台并发名额』『已用 / 上限』曾与表头同为 `text-xs font-medium` 但渲染不一致。排查用真实 Chromium 加载 e2e 构建产物的 CSS 计算样式，h4、span、th 三者均为 500/12px——类名层面早已一致。为排除 h4 标签自身带来的差异，『后台并发名额』改为与『已用 / 上限』相同的 span（`aria-labelledby` 仍指向它）。随后人类在浏览器里测得表头实际字重是 600：Aura 主题给列标题文字（`.p-datatable-column-title`，token `datatable.column.title.font.weight`）默认 600，而 scoped 样式只作用在 `th` 元素上，自然盖不住内层 span。两处小节标题改为直接引用 `--p-datatable-column-title-font-weight`，th 的硬编码字重移除，此后跟随主题、不再硬编码。

每条明细原来把种类、次数、对象键、大小、时间、处置提示五段同样式的文字堆在一起，难以扫读。重设计：第一行只放加重的对象键，其余信息收成一排小 tag——带色的种类、观察次数、首次与最近发现合并成一条、含大小时一条精确字节数；处置提示不进列表，只随复制带出；复制按钮顶对齐。

随后人类要求管理页一律不写具体几点几分：页头和明细区的『最近更新』、存储审计卡的本轮开始与上次完成、TODO 行的扫描失败时刻，统一改为 `useAdminRelativeTime()` 的展开式相对时长（最多两个单位，如『1 天 2 小时前』）。`useAdminRelativeTime()` 顺带去掉返回值的前导空格。同日人类指示：高频修改期间不再每轮跑 e2e，人类点名才跑；期间只跑 ESLint、typecheck 和组件测试。

随后修复轮询刚成功时（时差为 0 或亚秒级）后缀在『前』『后』间来回跳的问题：precise 模式下不足一秒的时差直接显示『刚刚』，组件测试覆盖 0 秒与 400 毫秒未来偏移两种情形。

随后人类要求时间与『更新』调换语序并省略『最近』：页头和明细区统一写成『刚刚 更新』『10 分钟前 更新』。用户页的『取消选择（N）』按钮随后加进出动画：先试过横移加负 margin 收拢间距，但和 label 里选中数变化引起的宽度重排相互干扰，出现轻微左右位移；改为仅 0.15s 透明度过渡。『筛选条件』徽章从自研 `MyBadge` 改用 PrimeVue `Tag`（有筛选 warn、无筛选 secondary），与异常明细区的种类标签同一组件体系。Tag 默认 14px／700 字重，与内嵌 12px mono 表达式混排时，`align-items: center` 只做盒子居中而非基线对齐，两侧不同行高使基线错开、mono 一侧视觉偏上（原 `MyBadge` 两侧同为 text-xs，恰好不显形）；修法是 Tag 整体 `!text-xs !font-normal`，两侧同字号同行高后盒子居中等价于基线对齐，不用任何手动偏移。两处『刷新』按钮请求期间只 `disabled`，不再用 `loading` 的旋转图标——图标会被换成 spinner 引起一次跳动。

2026-11-23，人类验收通过：筛选条件恢复描边 `MyBadge` 并收紧清除按钮，用户卡片选中和取消选中时过渡边框颜色。

## LAW 解读

LAW 很短，下面是落到实现时我取的读法。读错了请指出。

| LAW 的说法 | 读法 |
| --- | --- |
| hover card 对“有权限之人”显示『控制台』 | 有『控制台·只读』以上权限的人，管理员包括在内 |
| 用户列表“实时” | 页面可见时每 2 秒重新请求一次，不是推送 |
| 卡片上“有一堆操作按钮” | 按钮只对有『控制台·完全』的人显示；只读者看到的卡片没有按钮 |
| 管理操作“需要权限：『控制台·完全』” | 每个操作接口都在服务端按这一级校验。这一级是管理员特有，所以实际只有管理员能操作 |
| “编辑”是打开对方主页 | 控制台自己不改资料，改资料在主页上做，属于账号板块 |
| LAW 没提筛选条件、命令栏、多选批量操作 | 它们是现有功能，LAW 不约束，由 AGENT-DESIGN 记录；不因为 LAW 没写就删 |

## 传统与工作经验

- 筛选条件的安全靠服务端的语法树白名单，浏览器里的语法检查只是为了及时提示。改筛选能力时改 [admin-filter.ts](../../../server/services/admin-filter.ts) 和它的测试，不要指望前端拦截。这个漏洞最初就是因为检查只在浏览器里。
- 新增可筛选的字段只改 `ADMIN_FILTER_FIELDS` 一处。密码哈希、令牌哈希这类字段不能加进去。
- 列表不订阅通知、只靠轮询，是因为在线状态这类内容没有写入事件可订阅。别的管理员做的改动也是靠这 2 秒一次的轮询看到的。
- 页码和每页条数要一起生效。分开改会发两次请求，第一次的结果还可能对不上页。所以查询条件存在一个整体的快照里，由 `refresh()` 一次换掉。
- 用户列表复用账号板块的 `format_profile_row()`。谁能看到手机号只在那一处定，控制台不另写一套。
- 取当前页的 SQL 里，`LIMIT` 和 `OFFSET` 的参数是转成字符串再传的。代码里没有注释说明原因，应是为了绕开 MySQL 预处理语句在这两个位置对数字参数的限制；要改回数字先在真实数据库上试。
- 页面上的操作入口按权限显隐只是为了界面干净，每个接口都在服务端重新校验。测权限时直接调接口。
- 命令栏为了在“没有正在选择补全项”时让回车直接执行，在输入框上抢先监听了键盘事件。动 PrimeVue 的 AutoComplete 版本或它的内部结构时先看这里。
- 用户和运行状态换着挂载，离开视图后它的轮询自然停止。视图里的状态不保留；要保留就得另想办法让轮询停下，别直接套 `KeepAlive`。
- 2026-11-12 最初的三个视图放在同一个页面里用切换按钮选，是照档案首页切『已发布 / 未发布草稿』的做法。当时没选的两种：拆成 `/admin/tasks` 这样的子页面，站里没有“同一板块多个子页面加导航”的先例，每页还要重复挂中间件和 `noindex`；全堆在一页，用户列表一页能到十几万条，下面的内容等于看不到，三处轮询也会同时跑。
- 阻塞要有明确原因和待办。仅有到期数或历史失败数时，界面保留事实供核对。任务、阶段和错误码的原值可用于查日志。
- 运行状态提供复制排查信息的入口。处置存储异常仍需核对，步骤见维护补充。
- 后台状态里和进程有关的部分只代表应答请求的那一个进程。界面上那句“不是所有实例的合计”不要删。
- 旧任务页曾用两个竖排交替放卡片。现行页面将任务、待办、运行情况列在同一张表里；桌面的四张详情卡会在轮询数据改变高度后重新贴合短列，手机和读屏顺序始终是后台任务、存储审计、当前进程、处理用时。
- 清单外的任务、认不出的环节和异常种类都照原文显示出来，不丢。服务端先加了新东西、界面还没跟上时，至少看得到。
- 新增公开参数曾经会让 `scripts/migration/frozen.test.ts` 失败：2026-11-12 时已冻结的 `20261101133000_content_webp.ts` 把公开参数的校验规则和生成结果打进了自己的产物，摘要跟着变。本轮想加轮询周期时撞上了，按冻结规则撤回了配置。2026-11-13 迁移架构改造后删除了所有 TS 迁移，这个问题不再存在，`statusPollIntervalSeconds` 配置已恢复。
