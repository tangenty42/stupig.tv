## LAW 解读

- **『自动更新』的快照例外**：“已强调是某个时间点的判断快照”读作界面上有文字写明，光是数据只读一次不算。删除确认框因此加了一句说明。
- **『提示和确认』的两种方式**：一步即可确认的用气泡，需要先展示检查结果的用对话框。这是现状的归纳，LAW 没有规定哪种操作用哪种。
- **『错误处理』的“告知用户”**：弹提示或在相应位置显示都算。401 不弹提示，因为退出登录本身就是告知。
- **『时间』的“及时更新”**：读作每秒更新一次当前时间，“几分钟前”这类说法随之变化。

## 其他出入

1. **退出登录绕开 tRPC 客户端。** `useAuth().logout()` 用 `$fetch` 直接请求 `auth.logout`，失败一律忽略。这是为了避免 401 处理再次调用 `logout()` 形成循环，代码有注释说明，记录在此。
2. **退出提示的实际显示时机。** 告别提示随 `onNuxtReady` 调度，整页刷新可能先完成。2026-11-25 修复 UI-B02 后，Toast 抑制按 Nuxt 应用实例存放，只在浏览器的退出流程启用。本页和跨标签退出都绕过 Nuxt 的短时间刷新防重。

## 传统与工作经验

- 首屏遮罩做成内联脚本，是因为它要在任何 JS 包加载前就盖住页面；15 秒兜底防止水合失败时遮罩永远不走。
- 明暗模式的服务端渲染只读 cookie，不读系统偏好，因为服务端拿不到；所以切换按钮也不提供“跟随系统”。
- 提示要等 `onNuxtReady` 再弹，否则水合期间弹出的提示会造成 mismatch。
- 确认气泡的定位自己算，因为 PrimeVue 4.5 只在点击文档时才重新对齐。
