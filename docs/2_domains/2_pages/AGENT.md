| 2 | 首页的随机表情要不要排除 🖕、💩 这一类 | “不管” | 不改代码。表情保持不筛选 |

两项的现状留在下面备查。

### 1. 不存在的网址显示什么

仓库里没有自定义的报错页（没有 `app/error.vue`，也没有兜底路由）。按 Nuxt 的默认行为，打开不存在的网址会显示框架自带的报错页：没有网站的顶栏和面包屑，文字也不是蠢猪的口吻。这一点是读代码得出的，没有实际打开过。

### 2. 首页的随机表情

`random_emoji()` 从 8 个 Unicode 表情区段里均匀抽取，能抽到一千一百个左右的表情，其中包括 🖕、💩 这一类。首页每 100 毫秒换一次，按这个速度，任何一个指定的表情平均不到两分钟就会出现一次。代码注释写明这是有意不维护清单，好让新表情自动进来。

## 其他出入

| 事项 | 现状 |
| --- | --- |
| 图片不在仓库里 | 首页的两张图只存在于对象存储。仓库里没有源文件，也没有上传脚本，换图要手工传到开发和生产两个桶 |
| 表情轮换不看系统设置 | 系统开了“减少动态效果”时仍轮换，正常每 100 毫秒，悬停档案链接时每 500 毫秒 |

## 传统与工作经验

- 两页上的文字都是作者的原话：『全能型人才』『蠢人，你在期待什么？』『暂时没啥好的联系方式』等等。宪章要求保留作者的『整活』原话，不限于带保护标记的内容。重构、调样式、抽组件时照搬原文，要改文案先问人类。规则见 [作者内容与保护标记](../../0_overall/AGENT-DESIGN.md#作者内容与保护标记)。
- 随机表情用 `useState()` 存，是为了让服务端抽到的那个随页面数据传给浏览器。换成普通的 `ref` 的话，两边各抽各的，首屏就会不一致。轮换放在挂载之后才开始，也是同一个原因。
- 样式表里拿不到站点图片的地址，因为地址的前半段来自运行配置。要在 CSS 里用图片时，由模板把完整地址写进 CSS 变量，样式再读变量，首页色带的 `--band-mask-url` 就是这么做的。
- `random_emoji()` 先按区段大小均匀抽码位，再用“默认以彩色表情显示”这个 Unicode 属性过滤。区段里有很多未分配或默认显示成单色符号的码位，不过滤会抽出空白方框。
- 新增站点图片时别忘了在 `app.storageAudit.staticKeys` 登记，否则存储审计会把它报成来路不明的对象。
- 浏览器测试里站点图片一律是灰色占位图，测不出图片内容。深色模式下的反色只能靠检查样式的计算值，看不出实际效果好不好。
- 页面的组件测试放在页面文件旁边，叫 `<页面>.nuxt.test.ts`。Nuxt 扫描路由时会跳过测试文件，不会多出一个路由。
- 测首页表情轮换时，用 `mockNuxtImport` 把 `random_emoji` 换成一个计数器。这样既能断言文字在变，也能在卸载后看计数器停没停，不用假时钟。首页的表情存在 `useState` 里，同一个测试文件里的各个用例共用一份，用例之间要 `clearNuxtState`。
