## 公共框架

总体 LAW 将各页面的共用设施归入公共框架，包括导航栏、悬浮确认框和数据更新器等。调查时的全站入口还包括面包屑、登录／注册弹窗及当前身份入口。

该领域可展开共用界面的展示、交互及数据更新行为。账号注册、登录等操作的业务规则归账号与权限；公共框架描述这些入口如何被承载，不另定义一套账号规则。

| 当前入口 | 承担的业务 |
| --- | --- |
| 全站公共框架 | 导航、面包屑、登录／注册弹窗及当前身份入口 |

其他页面通过变化通知和必要的重新读取获得更新。通知本身不代表某次用户操作已经成功，操作是否完成以服务端确认的结果为准；是否将这一行为作为正式约定，由人类核对。

## 账号与权限

### 身份与权限边界

- 『蠢猪小组』成员是 `SID#0.0.LAW` 指定的六名现实成员，不能根据注册成功、用户名或展示身份自动推定成员资格。
- 依据 `SID#0.0.LAW`，档案写权限和机密内容读取权限只能赋予成员账号，且授权过程由人类亲自操作。通过管理员身份间接获得这些权限，同样受此边界约束。
- 登录仅建立账号身份；读取机密内容、编辑档案和管理账号分别需要相应权限。
- 调查时的实现区分控制台只读、控制台完全管理、档案管理和机密读取；这些权限的具体含义需要人类核对。
- 页面上的隐藏、禁用和预览视角用于表达资格，不产生额外授权。

### 状态及对其他板块的影响

访问身份需要区分未登录、有效登录和登录已失效；权限另行判断。

| 变化来源 | 其他板块需要核对的结果 |
| --- | --- |
| 登录、退出、封禁或会话失效 | 当前身份展示及受限操作重新核对资格；失效身份不能继续提交受保护操作 |
| 权限调整 | 正文、附件和编辑能力按新权限重新判定；已打开页面不能仅凭旧展示状态继续放行 |

权限撤销阻止后续不再被允许的读取，不能撤回已经下载的副本。

## 蠢猪档案

本节集中保存原总体草案中过度展开的档案业务。正文、草稿、附件、上传和图片等可以继续拆成领域内部的页面或模块文档；它们之间的共同规则由档案领域总体 LAW 说明。

### 内部对象

| 对象 | 含义与归属 |
| --- | --- |
| 正式档案 | 已发布的正文和从正文提取的标题、标签、事件日期、说明、封面等信息；用于对外阅读 |
| 云端草稿 | 尚未发布的正文，既可以是全新档案，也可以是已发布档案的修改；由具备相应权限的编辑者共同使用 |
| 编辑会话 | 某个页面对草稿的编辑资格、尚未确认的输入和操作结果；与账号的登录会话分别管理 |
| 附件工作区 | 已发布档案所属的文件和目录，以及它们的名称、位置和访问属性 |
| 上传任务 | 将本地文件交付给某个工作区的过程；上传中的文件尚不能等同于已生效附件 |
| 图片版本 | 同一图片附件的正常展示、原图和可选删减内容；另存为产生独立附件 |
| 内容引用 | 正文对附件路径或其他档案的引用；名称变化需要联动已保存的正文与草稿 |

档案正文、云端草稿、附件工作区和上传任务分别具有自己的完成条件。调查时，“保存草稿”“发布正文”“附件操作生效”是三个不同动作，是否沿用这一业务选择见文末待确认事项。

### 状态与联动

| 对象 | 需要区分的状态 | 主要影响 |
| --- | --- | --- |
| 正文 | 正式内容、已确认保存的草稿、当前页尚未确认的输入 | 什么内容可对外展示、什么内容已可靠保存 |
| 编辑资格 | 可写、他处占用、断线或结果待核对 | 是否允许继续输入与提交；不可把只读恢复区当作已保存草稿 |
| 上传与图片处理 | 等待或传输、处理或待发布、生效、取消或失败 | 本地传输结束不代表附件已经可用 |
| 删除与文件回收 | 业务对象已删除、存储清理仍在进行 | 页面反馈与实际字节回收具有不同完成时间 |

| 变化来源 | 关联功能需要得到的结果 |
| --- | --- |
| 草稿发布 | 更新正式正文及档案摘要，让列表、详情和引用方获得对应变化 |
| 档案标题或附件路径变化 | 已保存的正文与云端草稿更新相应引用；当前页尚未上传的输入按其原有引用基线核对 |
| 附件上传、替换或图片处理完成 | 工作区呈现已生效结果，预览和正文引用可使用正确版本 |
| 删除或机密属性变化 | 重新判断读取资格和引用可用性；后台处理相关文件的后续回收 |

### 阅读与机密内容

普通访问者阅读正式内容，具体返回范围取决于当前身份。依据 `SID#0.0.LAW`，未经授权不能读取正文或附件中的机密内容。

调查时的实现会移除无权限访问者所见正文中的机密片段，并可向其提供机密图片的公开删减版。档案列表的标题、标签等摘要仍对外提供。因此，“正文含机密内容”不等于“整条档案记录不可被发现”。公开摘要、附件信息及删减版的确切边界，需要由人类确认并写入档案 LAW。

### 编辑、自动保存与发布

1. 编辑者取得草稿的编辑资格后修改正文；调查时采用共享草稿、单个页面独占写入。
2. 云端草稿的读取及编辑同时要求档案管理和机密读取权限，这一组合仍需人类核对。
3. 自动保存确认的是云端草稿；用户执行“保存／创建”后才发布正式正文。
4. 未发布的新草稿具有独立身份；首次发布后关联正式档案。附件工作区在首次发布后才开放。
5. 断线或操作结果不明时，先核对原操作，再继续修改。仅停留在当前页面的输入不能承诺在刷新或关闭后恢复。
6. 舍弃已发布档案的草稿恢复当前正式正文；舍弃从未发布的草稿删除该草稿。附件工作区此前已经生效的操作不会随正文草稿一起回滚。

### 附件、图片与引用

附件的改名、移动、删除、机密属性修改，以及上传和替换，各自独立提交。正文编辑页承载这些操作，但正文草稿不是附件操作的事务容器。

名字与路径变化联动相关引用；替换附件保留逻辑附件身份，更新其内容版本。图片另存为建立独立附件，删减版则属于原附件的额外公开表示。

调查时的删除操作允许留下悬空引用，并在操作前提供引用影响提示。提示不是锁，也不能得知其他页面尚未上传的输入。是否沿用允许悬空引用的策略，由人类确认。

## 运行与维护设施

总体 LAW 将变更通知、后台任务处理、数据迁移和版本更新归入同一板块。本轮继续保留这一合并，不采用此前 TMP-CHART 的拆分方案。

| 入口类别 | 调查时的职责 |
| --- | --- |
| 变化通知 | 提醒客户端重新获取事实，不承担正文或附件的持久保存 |
| 后台任务 | 完成异步处理，包括业务发布后的处理与文件回收等工作 |
| 维护工具 | 提供存储核对、迁移和恢复所需操作 |

该领域可以定义设施具备什么能力、处理的状态及结果。具体业务为什么触发任务、处理完成对业务意味着什么，由对应领域规定；人或 Agent 怎样执行发布、迁移和恢复，放到 `1_workflows/` 的相关流程中。

数据恢复需要按维护流程核对正文、元数据和文件；原调查没有发现业务回收站或通用“一键撤销全部变更”的能力，不能据此对用户承诺这些功能。
