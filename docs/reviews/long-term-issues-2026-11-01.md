# 长期问题与优先级（2026-11-01）

整理日期：2026-11-01（Asia/Shanghai）。代码基线：`3fdc491`，即 [PR #55](https://github.com/tangenty42/stupig.tv/pull/55) 合并后的 main。

本文汇总当前仍有效的长期问题和决策，不替代模块手册，也不授权执行生产变更。依据是[原架构审计](architecture-and-documentation-audit-2026-10-28.md)、[草稿实施记录](../designs/shared-cloud-draft-implementation-2026-10-30.md)及现行操作手册；原审计的早期描述须结合后续状态阅读。

## 当前结论

继续沿用模块化单体、MySQL 事实源、OSS 对象存储和 MQTT 通知。下一轮优先补恢复与运行证据、建立容量预算，再按实际增长调整架构。当前没有证据要求立即拆微服务、重建通用任务平台或整体替换编辑器／同步方案。

数据库自动备份由用户在 **1Panel** 配置，应用不新增重复调度。用户已手动走查生产业务，并补充报告取消机密后的引用／预览旧名问题；该问题及相关改名、移动、补全场景已在 #55 修复。其余人工验收结果、代理只读核对与尚缺的协议证据分别见[云端台账](../deployment/aliyun.md)。用户人工反馈不等同于逐请求 HTTP、缓存或恢复演练记录。

## 建议执行顺序

“近期”表示下一轮值得先安排，并不表示已经发现生产事故；“按触发条件”表示先观测或固定业务需求，再决定投入。

| 顺序 | 事项 | 建议时机 | 长期价值／启动条件 |
| --- | --- | --- | --- |
| L01 | 数据库、对象、配置的配套恢复演练 | 近期优先 | 验证现有备份能恢复当前业务，而不只证明有备份文件 |
| L02 | 发布材料长期保留与整体回退 | 近期优先 | 确保旧镜像、前端 chunk、ESA 配置与密钥版本仍可取得 |
| L03 | 授权、连接池和后台争用的观测与背压 | 近期先建立预算 | 提前发现排队、断租和读取授权延迟，避免靠猜测扩容 |
| L04 | 领域账本归档与保留政策 | 近期定边界，按增长实施 | 控制数据增长，同时保留幂等、去重和迟到任务保护 |
| L05 | 账号／资料通知的可靠性 | 按业务陈旧容忍度 | 明确哪些状态必须可靠送达、多久需要重新核对 |
| L06 | 全量工作区 API 与事务锁的扩展性 | 按规模和测量触发 | 大目录、大正文或高并发达到预算后再做分页／增量及锁优化 |
| L07 | 生产独立 worker 的交付 | 按后台争用触发 | 图片编码等重任务影响在线服务时隔离资源 |
| L08 | Markdown 多实现合同与混排语义 | 新增语法或出现体验问题时 | 降低解析、渲染、引用补丁和编辑器行为分歧 |
| L09 | OSS 对账范围及预热／清理验收 | 启用功能或存储增长时 | 补齐外部对象生命周期的证据与成本边界 |
| L10 | CI 状态与 Required 门禁简化 | 低优先级维护 | 减少重复汇总状态和等待时的误解，保留验证强度 |

## L01 · 配套恢复能力

**现状：** 1Panel 已由用户设置数据库自动备份；仓库有维护发布前备份与隔离恢复校验实现。已确认部分历史 SQL 仍存在，但尚没有当前 cloud-v1 的完整业务恢复演练证据。历史数量检查不能证明草稿、权限、引用、对象和账本一起可恢复。

**建议：** 沿用现有备份，先核对周期、保留、保存位置及可接受的数据丢失／恢复时限，再安排一次隔离演练。数据库恢复窗口必须与 OSS 对象版本窗口配套；旧记录中的 OSS 非当前版本 7 天保留需要实际读回，不能继续当作当前云配置。

**完成条件：** 在隔离目标恢复一致时间点的 main、draft、引用基线、权限及领域账本；核对对象摘要和读取授权；记录实际恢复耗时、缺失范围和处理办法。明确演练周期与执行责任。该项不要求先实现自助回收站或通用数据 down。

依据：[备份与恢复](../operations/backup-recovery.md)。

## L02 · 发布材料与回退

**已完成：** 应用／broker 使用 SHA tag 和实际 RepoDigest，发布回执记录提交、schema、settings 与草稿协议。不能再把“只有 latest、没有版本身份”列为当前缺陷。

**剩余问题：** CI artifact 有保存期限；镜像、旧前端 chunk、配置和 ESA 版本是否覆盖同一恢复窗口仍需管理。应用部署与 ESA 发布不是原子事务；代码回退也不会撤销数据库迁移。

**建议与完成条件：** 确定一份可恢复版本需要保留哪些材料、保存多久、由谁管理；验证可重新取得并交付同一版本。演练应用、SSR、CSS／JS、ESA 协议的配套恢复，并核对旧标签页的懒加载。首次跨回无租约旧协议等不兼容场景继续保持停写规则。无需为此立即建设完整蓝绿平台。

依据：[交付与回退](../deployment/github-acr.md)、[CSS 交付清单](../deployment/README.md#css-样式变更发布准备)。

## L03 · 在线授权与资源预算

**现状：** 读取授权仍依赖在线应用和数据库，连接池为 10 个连接、无限等待队列；后台与在线业务仍在应用模式中共享资源。已有后台状态汇总，但不足以构成端到端容量预算。

**建议：** 先观测数据库获取连接等待、事务／锁等待、授权延迟、草稿保活延迟、最老后台待办及失败率，结合当前流量确定预算。超过预算时采用有界等待、明确拒绝和重试反馈，再考虑分离 worker 或调整容量。

**完成条件：** 在前后台混合负载及连接池饱和时，系统能及时反馈；过期命令仍被拒绝，草稿和对象事实不丢失。不要以缓存授权决定改变现有每请求撤权合同。

依据：审计 A04／A05、[数据库池](../../server/lib/db.ts)、[后台工作](../modules/background-jobs.md)。

## L04 · 领域账本保留

**已完成：** #55 对到期命令回执压缩结果负载，保留永久去重身份；引用历史保留最近 200 个完整批次；outbox 确认送达后删除。2026-11-01 只读快照仅有 30 条过期命令回执、37 条 completed 传输会话，不能据此认定存在紧急容量压力。

**剩余问题：** 命令身份仍会增长，上传／图片终态、历史预算、已解决对账异常的长期归档与审计期限尚未统一。

**建议与完成条件：** 按领域列出“必须保留的安全事实、可压缩负载、可归档数据”，测量行数与字节增长，明确期限和查询需求后再实施有界清理。删除命令／传输身份前必须先设计服务端可验证的请求有效期协议；删除终态预热任务也须保住去重，避免重复花费额度。退役墓碑、未知外部结果、未完成清理责任和迁移 pin 不按通用 TTL 删除。

依据：审计 A06、[账本保留边界](../modules/background-jobs.md#账本保留与压缩)。

## L05 · 账号域通知

**现状：** Content 使用事务 outbox；账号／资料仍通过直接通知和进程内 MQTT 队列，重启或队列溢出可能丢消息。已有轮询、重连核对等补偿，但各资源的最大陈旧时间没有统一合同。

**建议与完成条件：** 先区分权限／会话、重要资料和派生在线状态。为需要可靠通知的变更接入事务 outbox，或明确可靠的最终重读机制；验证掉线、重启、消息丢失后的收敛时间。服务端授权继续使用当前权限，不能把 UI 通知迟到等同于服务端撤权失效；普通在线心跳不必逐条持久化。

依据：审计 A08、[实时同步](../modules/realtime.md)。

## L06 · 工作区规模与锁

**已完成：** Map／Set 已减少重复扫描，保存和纯续租路径也已减负。2026-10-30 本机万文件快照约 10MB，平坦／深度 8 的三次最大约 221／266ms；这些是有界本机测量，不是生产容量保证。

**剩余问题：** 工作区和档案列表仍有全量读取；scope 事务、全局标题锁及事务内引用改写构成扩展上限。

**建议与完成条件：** 先按真实目录规模、正文数量与写入并发复测。网络传输或渲染超出预算后做去重、分页或增量协议；锁等待超出预算后再评估拆锁。增量必须能发现缺口并安全重建；锁调整须覆盖移动、子树删除、上传预约、标题改写、死锁重试及草稿并发，不能直接移除锁。

依据：审计 A03／A04、[容量实施记录](../designs/shared-cloud-draft-implementation-2026-10-30.md#8-实施记录与发布边界)。

## L07 · 生产独立 worker

源码已有 worker／status 命令，生产精简镜像和 Compose 尚未提供独立 worker 交付。资源槽是每进程限制，不能当作集群总容量。

只有后台编码或扫描确实影响在线服务时，才优先补运行产物、编排、健康状态和资源预算。验收应覆盖 app／worker／disabled 切换、多实例租约、优雅退出和迟到外部结果对账。独立进程本身不会解决共享数据库的连接争用。

依据：审计 A05、[运行模式](../modules/background-jobs.md#运行模式)。

## L08 · Markdown 合同与产品语义

多套解析、渲染、CodeMirror、诊断和净化实现仍需共同维护。#55 已修默认名称同步、引用式标签、未保存输入和嵌套编辑补丁；仍应把类似场景放进同一组语法合同样例。

两个具体待决策点：图片与其他元素同段混排时，caption 目前没有独立 carousel 的同等合同；Setext 标题和表格扩展的编辑器着色／语法树与渲染能力仍有差异。先确定用户可见行为，再补跨层回归，保留自定义说明、UTF-16 位置、query／fragment 和原始文本边界。没有收益证据时不统一重写所有解析器。

冻结迁移依赖与在线解析入口分别维护；新增线上语法不能改变已执行迁移产物的摘要。

依据：审计 A10、[Markdown 当前合同](../modules/content/markdown.md)。

## L09 · 对象生命周期的证据与范围

现有全桶对账主要检查当前对象元数据，不覆盖历史版本、删除标记和未登记 multipart 的全桶专项盘点，也不是全量字节摘要审计。孤立对象自动清理默认关闭；预热启用与配额／缓存复用需独立验收。

优先按当前存储费用和异常类型决定专项盘点范围；启用清理前核对连续观察、对象身份及发布互斥，启用预热前核对生产冷回源、缓存复用和共享站点额度。不能从历史“无异常”计数或 Deploy 成功直接推断这些功能可以开启。云规则历史问题及共享站点设置调整也需要单独读回和验证。

依据：[OSS 对账](../operations/storage-audit.md)、[云端台账](../deployment/aliyun.md)、[对象生命周期](../modules/content/object-lifecycle.md)。

## L10 · CI 展示与门禁维护

PR #55 已核对：最多 13 项可见状态、9 项 Required。7 个实际测试 job 之外，还有 changes、三个固定 browser 状态、check 和 verified-tree；Required 名称齐全，browser-tests 未单独标 Required 不会绕过汇总门禁。

可低优先级将三个作用相同的 browser 汇总状态简化为单一稳定门禁。实施须同步调整 workflow、Ruleset 和说明，并验证代码 PR、纯文档 PR、测试失败／取消、main 代码树复用及部署触发；任何路径都不能留下永远 Expected 的必需状态或把失败当作成功。本轮不为减少显示数量而削减测试。

依据：[Check workflow](../../.github/workflows/check.yml)、[仓库门禁说明](../deployment/github-acr.md)。

## 暂停与不列为当前欠账的事项

- **旧浏览器验证暂停**：正式 Chrome／Edge 80、Safari 13.1 及完整旧引擎业务覆盖仍有缺口；按用户要求不继续推进。恢复时从[CSS 当前清单](css-official-apis-validation-2026-10-29.md#发布门槛与剩余工作)验收，不扩大已有结果。
- 封面同名公开附件回退、祖先原图追溯已退出运行时；冻结迁移与编辑来源版本校验保留，不能重新算作待剥除的历史运行逻辑。
- 共享云端草稿／租约、store 分工、旧附件公共 AES／上传类型、数据库专用配置入口及命令回执负载压缩已实现；后续改进应针对剩余边界。
- 通用 job／attempt／step 平台、微服务拆分、整体 AST／状态库替换、蓝绿平台、自助回收站和 AI agent 都不是当前收尾的必需前置；有明确业务需求时另立方案。
