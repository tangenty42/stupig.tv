## 总体范围

依据 `SID#0.0.LAW`，本项目为『蠢猪小组』官网，核心用途是编辑、保存和展示『蠢猪档案』，并提供配套账号及管理能力。

总体架构说明项目由哪些功能板块构成、每个板块承担什么职责，以及它们如何协作。各板块内部的业务对象、状态、操作、页面和组件，在 `2_domains/` 的对应文档中展开。

## 功能板块与职责边界

以下沿用现有总体 LAW 的六个板块；作为对功能表的候选补充，不另设一套分类。

| 板块 | 总体职责与协作边界 |
| --- | --- |
| 公共框架 | 为各页面提供公共 UI 与数据更新协调设施；使用账号与权限提供的身份信息，以及运行与维护设施提供的变更通知 |
| 账号与权限 | 管理账号、登录状态与权限信息，向其他板块提供身份及鉴权能力；具体业务操作还需满足所属板块的业务条件 |
| 平凡页面 | 承载网站主页和联系方式展示，使用公共框架提供的共用设施 |
| 管理控制台 | 承载用户及账号管理操作，使用账号与权限提供的用户信息、鉴权与账号管理能力 |
| 蠢猪档案 | 负责档案的阅读、编辑、发布及附件管理，使用账号与权限判定操作资格，并使用公共框架及后台处理能力 |
| 运行与维护设施 | 为网站提供变更通知、后台任务处理、数据迁移与版本更新等支撑；各业务板块定义相关任务的业务含义，维护执行步骤由 workflows 展开 |

功能关系图继续采用现有 `SID#0.1.LAW` 中的图，不在此重复维护。上述划分不要求板块与页面、代码目录或部署单元一一对应。

## 板块之间的协作

以下候选表述用于澄清职责交界，不展开每个领域的具体机制：

- 公共框架承载各板块共用的界面和数据更新行为。登录、注册等入口可以由公共框架承载，其业务规则仍归账号与权限。
- 账号与权限向管理控制台、蠢猪档案等板块提供身份及权限判定；管理控制台提供管理这些账号与权限的业务入口。
- 运行与维护设施提供变更通知，公共框架协调页面对变化的响应。哪些业务变化需要通知、影响哪些业务结果，由相应领域说明。
- 业务板块定义何时需要后台处理及其完成含义，运行与维护设施提供公共执行能力。
- 数据迁移、版本交付等作用于整个网站。总体文档交代其职责与影响范围，具体执行步骤在 workflows 中说明。

`SID#README` 明确将文档结构作为参考，因此总体 LAW 不必保留空的“状态”“操作”“入口清单”等章节。当前可以围绕功能板块、职责边界、关系图及确有必要的总体约定组织。
