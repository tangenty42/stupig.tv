## 通用模块

本节说明代码如何分工，以及关键共用能力的职责、入口和使用约定。模块之间的完整协作过程在后续“前后端协作”“数据更新”“SSR 水合”“后台任务”“维护方式”等章节展开。

通用性由职责和调用范围决定。同一目录中可以同时存在共用模块与领域专用模块；领域专用模块遵循这里的组织规则，其业务含义、状态与操作由对应领域文档说明。

### 前端

#### 组织与使用约定

| 位置 | 职责 | 使用边界 |
| --- | --- | --- |
| `app/composables/` | 封装响应式状态、上下文获取、生命周期及可复用的交互协调 | 需要 Vue/Nuxt 上下文的入口在 setup 或相应框架上下文中创建，再将取得的函数交给异步回调使用 |
| `app/utils/` | 提供工具算法、格式化和数据转换等底层逻辑 | 现有工程规则要求保持纯净，不调用 composable、不隐式读取配置；依赖和上下文由调用方显式传入 |
| `app/stores/` | 承载需要跨组件共享生命周期的客户端应用状态 | 与服务端查询缓存分工；服务端资源的取数和失效由同步取数层管理，业务状态的持久化规则由所属领域定义 |

页面与组件组合这些能力，处理展示和用户交互。composables 可以调用 utils；utils 的计算不反向获取页面上下文。前端应用层同时参与 SSR，需要区分服务端首屏执行与浏览器交互阶段，浏览器专用副作用按客户端生命周期启动和释放。

应用内引用通常使用 `~/` 指向 `app/`，使用 `@shared/` 取得前后端共享内容。纯类型引用与运行时依赖分别处理；服务端专用实现不能因为路径可解析而进入浏览器产物。

#### API 访问

[useApi](../../../app/composables/useApi.ts) 是页面和组件的业务 API 入口，按业务组织方法；[useTrpcClient](../../../app/composables/useTrpcClient.ts) 提供其下层的 tRPC 传输、SSR 请求身份传递和错误归一化。业务调用通常先通过 `useApi`；传输、身份等基础模块可按依赖关系使用底层入口，避免形成循环依赖。

`useApi()` 在 setup 中创建，事件与异步回调复用取得的方法。接口公共类型由共享契约及服务端路由类型提供，API 门面不另行定义一套相互独立的契约。客户端的参数检查和界面状态不替代服务端授权。

401 的退出登录处理集中在传输层；取数层避免再次弹出同一类错误。其他调用失败仍通过拒绝的 Promise 交给调用方或上层公共处理逻辑，调用方需要明确谁负责提示与恢复。请求如何进入服务端并组织业务操作，见 [SID#0.1.DESIGN：前后端协作](DESIGN.md#前后端协作)。

#### 查询与变更通知

[useSyncedData](../../../app/composables/useSyncedData.ts) 接收资源标识、取数函数及可选的数据／加载状态引用，通过引用或回调交付结果，并提供 `refresh` 入口。页面以它协调取数、资源变更后的刷新和错误处理；取数函数返回数据，展示状态的更新交给取数层处理。

[useDataSync](../../../app/composables/useDataSync.ts) 负责底层通知连接与资源订阅，包含普通资源与草稿私有通知通道。[Query / QueryClient](../../../app/utils/sync/query.ts) 负责查询复用、缓存、失效与刷新协调，订阅、时钟和轮询等环境能力由 composable 显式传入。

通常保留默认的共享查询方式；带有调用方独有行为的查询按需要使用独立模式。查询键决定哪些调用可以复用结果，资源标识决定订阅哪些变更；同一查询键应对应相同取数含义，修改查询键不会自动更换通知订阅范围。查询协调器按 Nuxt 应用实例管理，SSR 请求之间不共享用户查询状态。

可重新读取的服务端资源优先通过 `useSyncedData` 接入；不表示共享查询结果的原始事件可以直接订阅 `useDataSync`，调用方负责取消订阅。通知、失效、补读与轮询的完整关系见 [SID#0.1.DESIGN：数据更新](DESIGN.md#数据更新)。

#### SSR 状态与显示时间

[useSyncedState](../../../app/composables/useSyncedState.ts) 标识需要由同步取数层协调水合更新的状态。使用键和初始值创建时，它基于 Nuxt `useState`；包装已有引用时，仅增加同步状态标识，不会自动将普通 `ref` 变成可跨 SSR 传递的状态。

需要延续首屏结果的状态应由 Nuxt payload 承载，或保证服务端与浏览器首轮取数一致；传入已有引用时也遵循这一要求。同步标识使取数层可以在水合期间暂存更新，但不替调用方解决状态序列化和初始值一致性。

[useDisplayTimeContext](../../../app/composables/useDisplayTimeContext.ts) 提供可序列化的显示时间与时区上下文；[useReactiveDateNow](../../../app/composables/useReactiveDateNow.ts) 从该上下文派生响应式时间；[time 工具](../../../app/utils/time.ts) 使用显式传入的时间、时区等信息完成转换与格式化。[时区插件](../../../app/plugins/timezone.ts) 在服务端采用时区 cookie 或 UTC，浏览器完成首屏接管后再更新本地时区并启动时钟。

页面复用这些入口，避免各自创建相互独立的首屏时间基准或在渲染时读取浏览器时区。状态传递、水合期间更新及请求隔离的整体约定见 [SID#0.1.DESIGN：SSR 水合](DESIGN.md#ssr-水合)。

#### 共用交互

[useMyConfirm](../../../app/composables/useMyConfirm.ts) 封装确认浮层的发起方式，接收触发事件、提示内容和确认后的动作；[useMyToast](../../../app/composables/useMyToast.ts) 提供成功、提示和错误消息入口，统一接入现有展示设施。

两者依赖组件注入上下文，先在 setup 中取得能力，再供点击事件或异步处理使用。调用方决定何时需要确认、提示内容和后续业务操作；共用模块负责展示接入。确认操作不代表获得服务端权限，提示成功也不替代业务结果校验。调用层与公共取数层之间应明确提示责任，避免重复提示。

### 后端

#### 组织与使用约定

| 位置 | 职责 | 使用边界 |
| --- | --- | --- |
| `server/trpc/`、`server/api/` | 接收请求、执行输入与入口权限检查，调用服务并转换响应 | 传输入口保持明确的协议职责；业务操作交给 services |
| `server/services/` | 组织业务操作、业务查询、事务及跨设施协作，也承载通用服务能力 | 可以调用 lib 和其他职责明确的服务；领域服务持有自己的业务规则、状态转换与完成标准 |
| `server/lib/` | 封装连接、外部协议、设施接入和底层工具 | 提供 services 可复用的底层能力，不反向依赖 services |

主要依赖方向为“请求入口 → services → lib”；领域服务中的 repository 文件负责所属业务的数据访问，同样位于 services 内。层次用于明确职责，不要求每个函数都增加一层无实际作用的转发。

服务端通常通过 `@server/` 引用本层模块，通过 `@config/` 使用配置加载能力，通过 `@shared/` 复用公共契约。`@config/` 指向 `config/lib/`；独立脚本与测试需要由各自工具配置相应别名。私密配置、连接实例和服务端执行上下文留在服务端。

#### 数据库与外部设施接入

[db](../../../server/lib/db.ts) 提供共用 MySQL 连接池，统一连接参数及 UTC 会话时区。业务 SQL 与事务组织放在 services；同一事务中的相关操作使用同一事务连接，不在页面或传输入口直接拼接业务查询。

[aliyun-oss](../../../server/lib/aliyun-oss.ts) 提供对象操作、预签名等存储接入能力；[ESA 接入](../../../server/lib/esa.ts)、[短信](../../../server/lib/sms.ts)、[验证码](../../../server/lib/captcha.ts)等模块封装对应外部接口。它们接收业务层明确传入的操作参数，使用服务端配置访问设施。

调用方负责业务授权、对象归属和操作前置条件；设施模块仍执行自身必要的输入、协议和访问级别检查。一次外部调用成功，仅表示该设施操作的结果，跨数据库与外部设施的一致性、重试和业务完成判定由对应服务组织。配置的来源及公开边界见 [SID#0.1.DESIGN：配置系统](DESIGN.md#配置系统)。

#### 服务端变更通知

[sync](../../../server/lib/sync.ts) 的 `publish_refresh` 将资源变更封装为通知；[mqtt](../../../server/lib/mqtt.ts) 管理服务端连接与发布，并提供需要等待 broker 确认的发布入口。业务服务决定哪些成功变更需要通知哪些资源，底层设施负责消息发送。

当前蠢猪档案通过业务事务内的 outbox 记录和后续任务投递通知；其他领域仍有直接调用共享发布工具的路径。直接发布的内存缓冲不具备持久 outbox 的保证，broker 确认也不表示浏览器已经完成刷新。两条路径的可靠性边界及前端消费方式见 [SID#0.1.DESIGN：数据更新](DESIGN.md#数据更新)。

#### 通用后台执行

[create_background_runner](../../../server/services/background/runner.ts) 接收任务适配器，提供注册、唤醒、状态快照与关闭入口。适配器声明任务标识、执行间隔、资源占用和接收取消信号的执行函数，runner 负责进程内调度与并发协调。

[后台唤醒模块](../../../server/services/background/wakeup.ts) 提供本进程内的执行提示；持久任务记录与周期扫描仍是恢复处理的依据。领域任务负责领取与租约、幂等、检查点、重试、外部副作用回执和完成判定，runner 不自动提供持久队列或跨进程互斥。

应用内任务通过生命周期入口注册，关闭时停止接受新调度、发出取消信号并在期限内等待执行结束；任务需要配合处理取消，外部操作不会因为信号发出而自动撤销。默认应用内运行方式、注册与停止流程见 [SID#0.1.DESIGN：后台任务](DESIGN.md#后台任务)。

#### 错误与日志

[ApiError](../../../server/errors/ApiError.ts) 表达可预期的业务失败，包含状态码、面向用户的消息及经公共 schema 校验的可选错误数据。[tRPC 初始化](../../../server/trpc/init.ts)负责协议映射与公开错误输出；业务服务不直接组装传输层错误包。

[log](../../../server/lib/log.ts) 提供 `log_info`、`log_warn`、`log_error` 和 `error_fields`，以结构化 JSON 行记录事件与错误信息。调用方选择可记录的字段；日志工具不自动移除密钥、签名链接或业务隐私，也不以一条日志替代持久回执或任务状态。

对外错误与内部诊断信息分别处理，完整异常不能不经筛选就作为业务响应返回。请求层错误转换见 [SID#0.1.DESIGN：前后端协作](DESIGN.md#前后端协作)，日志查看、任务检查和恢复方式见 [SID#0.1.DESIGN：维护方式](DESIGN.md#维护方式)。

### 前后端共享

共享模块位于 `server/shared/`，通过 `@shared/` 引用。目录名称包含 `server`，但其公共运行时代码需要同时满足浏览器与服务端的使用条件；不得运行时引入配置 loader、数据库连接或服务端凭据。仅用于编译期的类型引用与运行时引入分别处理。

| 入口 | 职责 | 使用边界 |
| --- | --- | --- |
| [types/](../../../server/shared/types/) | 定义公共 API 数据、同步资源标识等跨端契约 | 类型约束不代替运行时校验；服务端私有类型留在 `server/types/` 或所属模块旁 |
| [schemas.ts](../../../server/shared/schemas.ts) 及相关共享 schema | 复用字段规则、表单契约和可公开数据结构 | 服务端在 [tRPC schemas](../../../server/trpc/schemas.ts) 中组织完整入口校验，并继续执行鉴权和业务条件检查 |
| [permissions.ts](../../../server/shared/permissions.ts) | 提供共用权限标识、结构与判定工具 | 前端据此组织展示；实际授权由服务端依据可信身份和状态判定，权限业务规则由“账号与权限”定义 |
| [api-error.ts](../../../server/shared/api-error.ts)、[content-reference-error.ts](../../../server/shared/content-reference-error.ts) | 声明并解析可跨端传输的结构化错误数据 | 只传递已声明且校验通过的公共字段；具体错误的业务含义由所属领域定义 |
| [settings.ts](../../../server/shared/settings.ts) | 提供前后端共用的公开业务参数入口 | 使用生成结果，不手工编辑生成文件；具体生成流程见“配置系统” |

共享目录中也包含领域专用的类型、校验和算法。将其放入共享目录表示两端需要复用，不改变其业务归属。公共契约集中维护，调用端通过组合使用，避免 API 门面、表单和服务端各自复制一套规则。

这里的 `@shared/` 是项目自定义别名，指向 `server/shared/`；Nuxt 的 `#shared/` 指向根目录下的 `shared/`，两者不可混同。共享模块与前后端入口如何形成完整调用关系，见 [SID#0.1.DESIGN：前后端协作](DESIGN.md#前后端协作)。
