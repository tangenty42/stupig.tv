# 备份、恢复与回滚

> 当前备份与恢复操作见 [SID#1.4.AGENT-DESIGN](../../docs/1_workflows/4_maintain/AGENT-DESIGN.md#备份与恢复)，验证边界与既有决定见 [SID#1.4.AGENT](../../docs/1_workflows/4_maintain/AGENT.md)。本文保留原始恢复演练、备份身份和历史核对结果，其结论只适用于记录的版本与范围。

仓库提供迁移回执、对象生命周期控制和部署失败恢复，但没有完整的自动备份调度、业务回收站或通用数据 down。生产备份位置、保留周期和恢复目标需要由运维明确配置并演练，不能根据 OSS 开启版本控制就判定已具备完整恢复能力。

## 需要共同保留的材料

数据库、对象版本、发布身份、外部配置与历史迁移材料的共同保存要求，见 [SID#1.4 日常备份](../../docs/1_workflows/4_maintain/AGENT-DESIGN.md#日常备份)。

## 当前工具能做什么

密文交付见 [SID#1.1 生产密文与提交钩子](../../docs/1_workflows/1_develop/AGENT-DESIGN.md#生产密文与提交钩子)，脱敏样本与生产备份的边界见 [SID#1.4 开发样本与重置](../../docs/1_workflows/4_maintain/AGENT-DESIGN.md#开发样本与重置)；发布回退范围见 [SID#1.3 失败后先确认停在哪一步](../../docs/1_workflows/3_deliver/AGENT-DESIGN.md#失败后先确认停在哪一步)。

OSS 当前版本删除、历史版本生命周期及永久删除是不同操作，实际保留能力需核对[桶配置](../deployment/oss.md)。旧版本还在不代表应用中存在可点选的恢复入口。

## 维护前备份流程

受控停写、在途请求登记、备份材料及隔离恢复验证见 [SID#1.4 备份与恢复](../../docs/1_workflows/4_maintain/AGENT-DESIGN.md#备份与恢复)；Maintenance Deploy 的适配条件、备份路径和失败边界见 [维护发布前备份](../../docs/1_workflows/4_maintain/AGENT-DESIGN.md#维护发布前备份)。

## 部署失败

先按 [SID#1.3 失败阶段](../../docs/1_workflows/3_deliver/AGENT-DESIGN.md#失败后先确认停在哪一步)定位，再保存对应的[日志与回执](../../docs/1_workflows/3_deliver/AGENT-DESIGN.md#日志与回执)。数据库或对象需要恢复时，按 [SID#1.4 恢复步骤](../../docs/1_workflows/4_maintain/AGENT-DESIGN.md#误操作后的恢复)核对版本兼容性及一致备份。

共享云端草稿的具体切换合同见[原切换记录](migrations.md#共享云端草稿切换)。旧 localStorage 内容由管理员自行处理，应用不导入或删除。

## 数据或对象误操作

停写并保留现场、隔离验证、处理恢复点之后的合法更新，以及按兼容版本恢复服务，统一见 [SID#1.4 误操作后的恢复](../../docs/1_workflows/4_maintain/AGENT-DESIGN.md#误操作后的恢复)。

## 仍需部署时明确的项目

备份频率、保留与恢复目标等尚未核对的范围，以及暂停新增自动化的既有决定，见 [SID#1.4 待核对与既有决定](../../docs/1_workflows/4_maintain/AGENT.md#待核对与既有决定)。执行恢复前仍须明确由谁授权停机、回滚和永久删除；以下历史演练不证明这些部署责任已落实。

- **历史版本读取权限：** 桶版本控制实测为 Enabled，但当前应用身份对带 `versionId` 的元数据请求返回 403。随后只查询当前元数据，并严格比较返回的 version ID；395 个精确匹配证明备份版本当前仍在，不证明它们成为非当前版本后可被恢复。不能为演练放宽应用账号权限；后续应核对独立恢复身份的版本读取权限。

- **附件字节：** 395 个对象在备份中有 SHA-256 基线，但本轮没有取回内容或重新计算摘要。ETag／大小／版本匹配不替代字节恢复；头像基线不齐也需单列处理。
